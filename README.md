# 游戏服务器

基于 **Go 1.22** 的分布式游戏服务端，采用**微服务架构**（gRPC + Redis + MySQL），实现了登录/会话、匹配、实时对战（**帧同步 + 状态同步双模式**）与排行榜的完整闭环。

## 特性

- **微服务架构**：`center`（服务发现）/ `login`（账号）/ `gateway`（网关）/ `game ×2`（战斗）/ `rank`（排行榜）共 6 进程，一键启动
- **双模式对战**：
  - **帧同步**（默认，`mode=0`）：服务器广播本帧输入，客户端本地确定性模拟，按逻辑帧号计冷却；首帧附带一次全量初始状态作为开局基线
  - **状态同步**（`mode=1`）：服务器每 tick 广播权威快照，客户端仅渲染
- **权威服务端**：胜负结算、超时判定均在服务器，帧同步模式下客户端模拟仅用于表现
- **跨实例匹配**：Redis ZSET 匹配池按模式分池，Lua 脚本原子配对，多 game 实例不抢人、不撞房号
- **顶号踢线**：同一账号二次登录时旧连接收到明确原因通知（`Kick`）后断开
- **断线重连**：局间 token 复用重新登录续玩（局中掉线按判负处理）
- **排行**：Redis ZSET 实时 TopN（胜 +10 / 负 +1，只增不减）
- **持久化**：MySQL 玩家表（密码加盐哈希存储）

## 架构

```
                         ┌─────────────┐
  客户端 ── TCP/自定义 ──▶│  Gateway 网关 │  连接管理 / 协议分发 / 心跳 / 路由 / 推送
                         └──────┬──────┘
                gRPC            │ gRPC（PushSnapshot / PushFrame / PushResult）
                 ▼              ▼              ▼
         ┌──────────┐   ┌────────────┐   ┌────────────┐
         │  Login   │   │   Game     │   │  Center    │
         │  登录服   │   │  游戏服 ×N  │   │  中心服     │
         └────┬─────┘   │ 房间/双模式模拟 │   │ 会话/服务发现 │
              │         └─────┬──────┘   └─────┬──────┘
              ▼               ▼                ▼
        ┌──────────┐    ┌────────────┐   ┌────────────┐
        │  MySQL   │    │   Redis    │   │    Rank    │
        │ 玩家存档  │    │ 会话/匹配/排行 │   │  排行榜服   │
        └──────────┘    └────────────┘   └────────────┘
```

| 进程 | 端口 | 职责 |
|---|---|---|
| `center` | 9100 (gRPC) | 服务注册/发现、token 校验 |
| `login` | 9200 (gRPC) | 账号注册/认证（MySQL），签发 token |
| `gateway` | 8000 (TCP) + 9300 (gRPC) | 客户端接入、协议路由、会话管理、推送 |
| `game-1` / `game-2` | 9400 / 9401 (gRPC) | 房间管理、匹配、帧同步/状态同步模拟 |
| `rank` | 9600 (gRPC) | 排行榜（Redis ZSET） |

## 快速开始

### 前置依赖

- Go 1.22+
- Redis 运行中
- MySQL 运行中
- protoc（protobuf 编译器）

### 步骤

```bash
# 初始化数据库
mysql -u root -p < scripts/init_db.sql

# 构建
./build.sh

# 启动所有服务
./start_all.sh
```

### 真人上手

```bash
# 自动机器人对打
python3 client/auto_bot.py --bots 2 --mode 0

# 交互客户端
python3 client/interactive_client.py --mode 0
```

## 同步模式说明

| | 帧同步（`mode=0`） | 状态同步（`mode=1`） |
|---|---|---|
| 服务器下行 | 本帧输入 `FrameData` | 计算结果快照 `StateSnapshot` |
| 客户端 | 本地确定性模拟（表现 + 预测） | 仅渲染服务器结果 |
| 冷却判定 | 按逻辑帧号（20Hz 下与墙钟等价） | 每 tick 广播快照 |
| 胜负结算 | 服务器权威（本地模拟仅供表现） | 服务器权威 |
| 匹配池 | `match:pool:fs` | `match:pool:ss` |

两种模式互不配对，按 `MatchReq.mode` 分池匹配。

## 技术栈

- **语言**：Go 1.22
- **通信**：gRPC + Protocol Buffers
- **数据库**：MySQL（玩家数据）+ Redis（会话、匹配、排行）
- **架构**：微服务 + 事件驱动
